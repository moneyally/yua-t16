버전 0.1 (2026-09-11).

**SSOT 방향**: `docs/DESIGN.md`(수학·숫자 형식) → **이 문서**(디스크립터·레지스터 바이트 레이아웃)

## 1. 숫자 형식 (DESIGN.md 3절 재확인)

| 형식 | 폭 | 범위 | 쓰는 곳 |
|---|---|---|---|
| **Q1.15** (부호 있음) | 16b | [-1.0, +0.999969...] | `S`, `q`, `k`, `v`, `o` |
| **UQ1.15** (부호 없음) | 16b | [0, 2) — **0x8000 = 1.0 정확** | `alpha_uq15`, `beta_uq15` |

**1.0 초과(`> 0x8000`)는 미정의다.**

| 구현 | 동작 |
|---|---|
| 골든 모델 (`sim/golden/deltarule.py`) | `ValueError`. 조용히 처리하지 않는다. |
| RTL | **`0x8000` 으로 클램프**하고 트레이스 링에 `CLAMP_EVENT` 를 남긴다. `DR1_CLAMP_COUNT` 증가. 디스크립터는 계속 실행된다 (fault 아님). |

이유: 호스트 버그로 α>1 이 들어오면 상태가 발산한다. 조용히 발산시키는 것보다
클램프하고 **세는** 것이 낫다. 골든이 예외를 내는 것은, 골든은 검증 기준이라
미정의 입력을 받으면 안 되기 때문이다.

## 2. Opcode

기존 opcode 와 충돌하지 않는 `0x5x` 블록을 쓴다.

| 값 | 이름 | 설명 |
|---|---|---|
| 0x01 | `NOP` | (기존) |
| 0x02 | `GEMM` | (기존) |
| 0x03 | `KVC_OP` | (기존) |
| 0x04 | `VPU_OP` | (기존) |
| 0x10 | `MXU_FWD` | (기존, G3) |
| 0x20 | `BACKWARD` | (기존, G3) |
| 0x30 | `OPTIMIZER` | (기존, G3) |
| 0x40 | `COLLECTIVE` | (기존, G3) |
| **0x50** | **`DELTA_INIT`** | 상태 슬롯을 0 으로 |
| **0x51** | **`DELTA_STEP`** | 토큰 1개 처리 |
| **0x52** | **`DELTA_DUMP`** | 상태 전체를 스크래치로 (검증용) |

**구현 상태 (W7)**: **셋 다 동작한다.** `dr1_top` 이 `DELTA_STEP` 전체 경로
(q/k/v 적재 → p=S·k → err → 행 갱신 → o=S_next·q → o 쓰기)를 돌리고,
`desc_fsm_v2` 의 유효 opcode 목록에 0x50/0x51/0x52 가 전부 들어 있다.
골든 `step()` 과 **100토큰 비트 일치** (`tb/tb_dr1_harness_rtl.py`).

## 3. 디스크립터 레이아웃 (64바이트)

**기존 필드 위치를 유지한다.** `opcode@0`, `act_addr@16`, `wgt_addr@24`, `out_addr@32`,
`CRC@63` 은 `rtl/desc_fsm_v2.sv` 가 이미 그 위치에서 뽑는다. DR1 은 그 자리를 재사용하고
비어 있던 예약 영역만 채운다. **RTL 의 기존 필드 추출 로직은 손대지 않아도 된다.**

타임아웃은 디스크립터 필드가 아니다 — `desc_fsm_v2` 의 `timeout_cycles` 포트로 들어온다
(레지스터 설정값). 기존과 동일.

### 3.1 공통 (모든 DR1 opcode)

| 오프셋 | 크기 | 필드 | 형식 | 설명 |
|---|---|---|---|---|
| 0 | 1 | `opcode` | u8 | 0x50 / 0x51 / 0x52 |
| 1 | 1 | `slot` | u8 | 상태 슬롯 번호. **v1 은 0 만 유효** (`DR1_NUM_SLOTS`=1) |
| 2 | 2 | `reserved0` | — | 0 이어야 한다 |
| 4 | 4 | `reserved1` | — | 0 이어야 한다 |
| 8 | 8 | `reserved2` | — | 0 이어야 한다 (기존 레이아웃의 예약 영역) |
| 63 | 1 | `crc8` | u8 | 바이트 [0:62] 에 대한 CRC-8 (다항식 0x07). **기존과 동일** |

### 3.2 `DELTA_INIT` (0x50)

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 1 | `opcode` | 0x50 |
| 1 | 1 | `slot` | 0으로 만들 슬롯 |
| 2..62 | 61 | `reserved` | 전부 0 |
| 63 | 1 | `crc8` | |

주소 필드를 쓰지 않는다. 완료 시 `done_ok`.

### 3.3 `DELTA_STEP` (0x51)

| 오프셋 | 크기 | 필드 | 형식 | 기존 필드 | 설명 |
|---|---|---|---|---|---|
| 0 | 1 | `opcode` | u8 | `opcode` | 0x51 |
| 1 | 1 | `slot` | u8 | — | 상태 슬롯 |
| 2 | 2 | `reserved0` | — | — | 0 |
| 4 | 4 | `reserved1` | — | — | 0 |
| 8 | 8 | `reserved2` | — | — | 0 |
| **16** | 8 | `q_addr` | u64 LE | `act_addr` | q 벡터 스크래치 주소 |
| **24** | 8 | `k_addr` | u64 LE | `wgt_addr` | k 벡터 스크래치 주소 |
| **32** | 8 | `o_addr` | u64 LE | `out_addr` | o 벡터 출력 주소 |
| 40 | 4 | `reserved3` | — | `Kt` | DR1 은 쓰지 않는다. 0 |
| **44** | 8 | `v_addr` | u64 LE | — | v 벡터 스크래치 주소 |
| **52** | 2 | `alpha_uq15` | **UQ1.15** | — | 게이트 α. 0x8000 = 1.0 |
| **54** | 2 | `beta_uq15` | **UQ1.15** | — | 학습률 β. 0x8000 = 1.0 |
| 56 | 7 | `reserved4` | — | — | 0 |
| 63 | 1 | `crc8` | u8 | `crc8` | |

벡터 크기는 `d` 개 × 2바이트 (Q1.15). v1 `d=16` → 32바이트.

### 3.4 `DELTA_DUMP` (0x52)

| 오프셋 | 크기 | 필드 | 기존 필드 | 설명 |
|---|---|---|---|---|
| 0 | 1 | `opcode` | `opcode` | 0x52 |
| 1 | 1 | `slot` | — | 덤프할 슬롯 |
| 32 | 8 | `dst_addr` | `out_addr` | 상태 S 를 쓸 주소 |
| 그 외 | | `reserved` | | 0 |
| 63 | 1 | `crc8` | `crc8` | |

덤프 크기는 `d × d × 2` 바이트. v1 `d=16` → 512바이트.

**W7 현재 상태**: `dst_addr` 로 **실제로 쓴다** (`rtl/dr1/dr1_scratch.sv`).
행 우선 스트림 포트(`dump_valid`/`dump_row`/`dump_data`)도 그대로 나온다 —
파형에서 행 단위로 보기 편해서 남겨 두었고, 테스트는 **메모리 쪽**을 본다.


### 3.5 벡터·상태 평탄화 규칙

RTL 의 `q_flat` / `k_flat` / `v_flat` / `state_sram.rd_data` 는 모두 이 규칙을 따른다:

```
원소 i  =  bits[i*W +: W]          (i=0 이 최하위, W=16)
```

상태 `S` 의 `DELTA_DUMP` 순서는 **행 우선(row-major)** 이다:

```
행 r 의 워드 = pack_vec(S[r])      r = 0, 1, ..., d-1 순서로 연속
```

Q1.15 는 **부호 있는** 16비트다 — 평탄화할 때 2의 보수 비트패턴으로 넣고,
풀 때 부호를 복원한다.

바이트로 내릴 때는 리틀엔디언이다. 평탄화 규칙(원소 i 가 낮은 비트)과
리틀엔디언이 일치하므로 **바이트 순서 = 원소 순서**다.

**구현 단일 출처: `tools/orbit_pack.py`**
(`pack_vec` / `unpack_vec` / `pack_state` / `unpack_state` / `bytes_of_vec` / `vec_of_bytes`).
RTL 테스트벤치와 `CocotbDut` 이 **이 함수만** 쓴다. 규칙이 두 곳에 있으면
한쪽을 고칠 때 다른 쪽이 조용히 틀린다 (`docs/BUGS.md` BUG-006 과 같은 종류).

### 3.6 스크래치 메모리와 배치 (W7 신설)

`DELTA_STEP` 의 `q/k/v/o` 주소와 `DELTA_DUMP` 의 `dst_addr` 는 **DR1 온칩 스크래치
(`rtl/dr1/dr1_scratch.sv`) 안의 바이트 오프셋**이다. 외부 메모리 주소가 아니다
(DDR/HBM 경로는 이 레포에 없다 — `docs/DESIGN.md` 10절).

| 항목 | 값 |
|---|---|
| 크기 | **1024 원소** × Q1.15 = 2KB |
| 원소 인덱스 | `바이트 주소 / 2` |
| 호스트 접근 | MMIO 창 **`0x8033_1000` ~ `0x8033_1FFC`**. 32비트 워드 하나 = 원소 하나 (하위 16비트) |
| 읽기 지연 | 1사이클 → **호스트는 같은 주소를 두 번 읽는다.** 첫 읽기가 주소를 걸고 두 번째에 값이 나온다 |

호스트가 쓰는 표준 배치 (`tools/orbit_mmio_map.dr1_scratch_layout(d)` 가 단일 출처):

| 원소 인덱스 | 바이트 | 용도 |
|---|---|---|
| `0 .. d-1` | `0` | `q` |
| `d .. 2d-1` | `2d` | `k` |
| `2d .. 3d-1` | `4d` | `v` |
| `3d .. 4d-1` | `6d` | `o` (결과) |
| `512 .. 512+d²-1` | `1024` | `DELTA_DUMP` 목적지 |

이 배치는 **호스트 규약**이다 — 하드웨어는 주소만 받는다. 다만 한 곳에만 적어 둔다
(테스트벤치와 HAL 이 같은 함수를 쓴다).

**호스트가 `DR1_STATUS.busy` 가 1 인 동안 스크래치를 쓰면 안 된다.** 같은 주소에
두 포트가 동시에 쓰면 미정의다.

> **크기 제약**: 스크래치 1024 원소로는 **d=64 의 덤프가 들어가지 않는다**
> (64² = 4096 원소, 필요량 4608). `dr1_scratch_layout(64)` 는 기본 크기로 부르면
> `ValueError` 를 낸다 — 조용히 넘어가지 않는다.
>
> **d=64 는 스크래치를 키우면 동작한다** (2026-09-11 확인).
> `dr1_scratch_layout(64, 8192)` 로 배치를 잡고 RTL 은 `SCRATCH=8192` 파라미터로
> 빌드한다. 골든과 20토큰 비트 일치, 462사이클/토큰 (`tb/tb_dr1_d64.py`).
> `g2_ctrl_top` 통합 빌드는 면적 때문에 **d=16 그대로**다 (docs/DESIGN.md 6.4절).

## 4. 실패 조건 → `done_err`

완료 신호는 `docs/DESIGN.md` **5.1절** 계약을 그대로 따른다
(`done_ok` / `done_err` / `done_pulse`, 한 트랜잭션에 ok/err 중 **정확히 하나**).
완료 IRQ(`DESC_DONE`)는 `done_ok` 에만 걸린다. 실패는 `TC0_FAULT` 로 보고된다.

기존 fault code 에 두 개를 추가한다:

| fault_code | 이름 | 조건 |
|---|---|---|
| 0x01 | `ILLEGAL_OPCODE` | (기존) |
| 0x02 | `CRC_MISMATCH` | (기존) |
| 0x03 | `TIMEOUT` | (기존) |
| 0x04 | `RESERVED` | (기존) |
| **0x05** | **`DR1_BAD_SLOT`** | `slot >= DR1_NUM_SLOTS`. v1 은 `slot != 0` 이면 전부 |
| **0x06** | **`DR1_UNALIGNED`** | `q/k/v/o/dst` 주소가 **16바이트 정렬**이 아님 |
| **0x07** | **`DR1_UNIMPL`** | 이 빌드에 없는 DR1 경로. W6 에서는 `DELTA_STEP` 이었다. **W7 에서 STEP 이 구현되어 지금은 아무도 내지 않는다** — 코드는 남겨 둔다 |
| **0x08** | **`DR1_ADDR_RANGE`** | 주소가 스크래치 밖이다. `DELTA_STEP` 은 원소 `addr/2 + d ≤ SCRATCH`, `DELTA_DUMP` 은 `addr/2 + d² ≤ SCRATCH` 여야 한다. 안 잡으면 다른 벡터를 덮어쓴다 |

16바이트 정렬인 이유: 스크래치 SRAM 의 데이터 폭이 128비트다
(`rtl/act_sram.sv` 의 `wdata [127:0]`). 정렬되지 않은 주소는 한 번의 접근으로 읽을 수 없다.

`alpha_uq15`/`beta_uq15` 가 `0x8000` 을 넘는 것은 **fault 가 아니다.**
클램프하고 `DR1_CLAMP_COUNT` 를 올린 뒤 계속 실행한다 (1절).

## 5. 레지스터 추가분

새 블록 **`DR1` = `0x8033_0000`** (기존 `OOM`=0x8032_0000 과 `TC0`=0x8034_0000 사이의 빈 공간).

| 주소 | 이름 | 접근 | 리셋 | 설명 |
|---|---|---|---|---|
| `0x8033_0000` | `DR1_STATUS` | RO | 0 | `[0] busy`, `[11:4] last_slot` |
| `0x8033_0004` | `DR1_SAT_COUNT` | W1C | 0 | 포화(saturate) 누적 횟수. 골든의 `sat_count` 와 대응 |
| `0x8033_0008` | `DR1_CLAMP_COUNT` | W1C | 0 | α/β 가 0x8000 으로 클램프된 누적 횟수 |
| `0x8033_000C` | `DR1_CYCLES` | RO | 0 | **마지막** `DELTA_STEP` 이 걸린 사이클 수 |

**W1C 규칙은 기존과 동일하다** (`IRQ_PENDING`, `TC0_FAULT_STATUS` 와 같다):
쓴 비트에 대응하는 비트를 0 으로 만든다. 카운터를 0 으로 되돌리려면
**읽은 값을 그대로 다시 쓴다**. 하드웨어 증가와 W1C 클리어가 같은 사이클에 겹치면
**증가가 이긴다** (set-wins) — 기존 `irq_ctrl` 과 동일한 규칙이다.

### 5.1 `DR1_STATUS` 비트

| 비트 | 이름 | 설명 |
|---|---|---|
| 0 | `busy` | DR1 이 토큰을 처리 중 |
| 3:1 | — | 예약 (0) |
| 11:4 | `last_slot` | 마지막으로 접근한 슬롯 번호 |
| 31:12 | — | 예약 (0) |

### 5.2 트레이스 이벤트 추가

| 값 | 이름 | 언제 |
|---|---|---|
| 1 | `DESC_DISPATCH` | (기존) |
| 2 | `DESC_DONE` | (기존) |
| 3 | `DESC_FAULT` | (기존) |
| 4 | `Q_OVERFLOW` | (기존) |
| **5** | **`SAT_EVENT`** | 포화 발생 (`docs/DESIGN.md` 7절 I4) |
| **6** | **`CLAMP_EVENT`** | α/β 클램프 발생 |

## 6. 사이클 예산 (DESIGN.md 6절, **미검증 추정**)

`DR1_CYCLES` 가 실측값을 준다. DESIGN.md 6절의 d=64 추정치는 ~210 사이클이고
목표는 ≤256 이다. **RTL 이 아직 없으므로 전부 추정이다.**
W8 에서 이 레지스터 값과 DESIGN.md 6절 표를 대조한다.

## 7. 이 문서가 정하지 않는 것

- 스크래치 SRAM 의 주소 맵 (호스트가 MMIO 로 채우는 방식) — v1 범위이지만 W5 에서 정한다.
- 다중 슬롯 (`DR1_NUM_SLOTS > 1`) — v2.
- BF16 — v2. `docs/DESIGN.md` 10절.
