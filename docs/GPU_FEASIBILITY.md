## 2. "4090급"을 만들려면 필요한 것 7가지

그래픽카드는 연산기 하나가 아니다. 없으면 카드가 안 되는 것만 적는다.

| # | 축 | 내용 |
|---|---|---|
| 1 | **연산 코어** | SIMT 파이프라인, 워프 스케줄러, 레지스터 파일, 특수함수 유닛 |
| 2 | **그래픽 고정기능** | 래스터라이저, 텍스처 유닛, ROP, 지오메트리, RT 코어 |
| 3 | **메모리 서브시스템** | GDDR6X PHY + 컨트롤러, L2, 캐시 일관성 |
| 4 | **I/O·디스플레이** | PCIe Gen4 x16 엔드포인트, HDMI/DP + **HDCP**, 비디오 인코더/디코더 |
| 5 | **물리 구현** | 합성·P&R·타이밍 클로저·DFT·패키징·전력 그리드 (EDA 툴 라이선스) |
| 6 | **드라이버** | 커널 모듈 + 유저모드 컴파일러 + Vulkan/DX/OpenGL 런타임 |
| 7 | **적합성·호환성** | Khronos Adopter 프로그램 통과, WHQL, **게임별 실측 대응** |

## 3. "Claude가 하면 다르다" — 축별로 정직하게

이 질문이 핵심이다. 감정 빼고 축별로 본다.

| 축 | LLM 이 판을 바꾸나 | 근거 |
|---|---|---|
| 1 연산 코어 RTL | **O (크게 도움)** | 이 레포가 증거다. W5~W6 2주에 RTL 6개 + tb 8개 + 게이트 통과 |
| 6 드라이버 **코드 작성** | **O** | 분량 많고 패턴화된 일이라 LLM 이 잘한다 |
| 검증 체계 | **O (우리 강점)** | 골든↔RTL 비트 대조 + 오류 주입. `sim/golden` ↔ `rtl/dr1` 1:1 |
| 2 그래픽 고정기능 | **△** | 알고리즘은 공개돼 있다. 그러나 화면에 픽셀이 틀리게 찍히는 것은 실물에서만 안다 |
| 3 메모리 PHY | **X** | 4절 참조. **살 수가 없다** |
| 5 물리 구현 | **X** | Cadence/Synopsys 라이선스 연 수억 [추정] + 파운드리 PDK 계약. 코드 문제가 아니다 |
| 7 적합성·게임 호환 | **X** | 수천 타이틀을 **실제로 돌려봐야** 안다. 실측을 대신할 수 없다 |
| 테이프아웃 비용 | **X** | $40~50M. 글 잘 쓴다고 안 깎인다 |

### 3.1 드라이버가 얼마나 걸리는지 — 실제 사례 [검색]

**NVK** (Mesa 의 NVIDIA용 오픈소스 Vulkan 드라이버):
- 2022-10 발표 → 2023-10 Vulkan 1.0 적합 → 2024-02 Vulkan 1.3 적합
- 주 저자 Faith Ekstrand + Karol Herbst + Dave Airlie (Red Hat/Collabora)

**약 1년 반, 세계 최상위 그래픽 드라이버 전문가 3명.**
그런데 이건 **가장 쉬운 조건**이다:
- 하드웨어가 **이미 존재하고 정상 동작**한다 (NVIDIA 실리콘)
- nouveau 의 십수 년 리버스 엔지니어링 자산이 있다
- 버그가 나면 **드라이버가 틀린 것**이다 — 원인 후보가 하나다

우리가 새 하드웨어를 만들면 **하드웨어 버그와 드라이버 버그를 동시에** 디버깅한다.
LLM 은 코드를 쓰지만, **둘 중 어느 쪽이 틀렸는지는 실물에서만 나온다.**

### 3.2 적합성은 "통과"가 아니라 "자격" [검색]

Vulkan 은 **Khronos Adopter 프로그램**을 통과해야 이름·로고를 쓸 수 있다.
CTS 소스를 받아 포팅하고, 결과를 제출해 워킹그룹 승인을 받아야 한다.
DirectX WHQL 은 마이크로소프트의 별도 절차다.
**두 개 다 조직 대 조직의 절차**이고, 개인이 우회할 수 있는 종류가 아니다.

## 4. 막히는 지점 하나만 꼽으면: **메모리** [검색]

4090 의 1008 GB/s 는 **GDDR6X** 에서 나온다. 그런데:

- GDDR6X 는 **JEDEC 표준이 아니다.** Micron 이 NVIDIA 와 공동 개발한 사실상 독점 규격이다
- **Micron 이 유일 공급자**이고, PAM4 시그널링이라 NVIDIA 도 전용 PHY·컨트롤러를 새로 만들어야 했다
- 독점 성격 때문에 **서드파티 IP 가 사실상 없다**

표준 GDDR6 로 가면 IP 는 있다 (Rambus, Northwest Logic, Cadence, Synopsys, Avery [검색]).
그러나 그 순간 **"4090급"이 아니게 된다** — 대역폭이 목표의 핵심이기 때문이다.

즉 4090급 대역폭은 **설계 실력의 문제가 아니라 조달의 문제**다. 돈이 있어도 규격을 못 산다.

## 5. FPGA 로 하면? — 오픈소스 최고 사례와 비교 [검색]

**Vortex** (Georgia Tech, MICRO-54, arXiv 2110.10857): RISC-V ISA 를 SIMT 로 확장한
**풀스택 오픈소스 GPGPU**. RTL + 사이클 정확 모델 + LLVM 컴파일러 + POCL 기반 OpenCL.
Xilinx/Altera FPGA 에서 실제로 돈다.

| | Vortex (Stratix 10 FPGA) | RTX 4090 |
|---|---|---|
| 코어 | 32 | — |
| 주파수 | 200 MHz | ~2.5 GHz |
| **FP32 성능** | **25.6 GFLOPS** | **~82,600 GFLOPS** |

**약 3,200배 차이다.** 이건 대학 연구팀이 수년간 만든, 이 분야 최고 수준의 오픈 FPGA GPGPU다.
FPGA 로는 4090급이 **물리적으로 불가능**하다 — 논리 용량과 클럭이 두 자릿수씩 모자란다.

참고로 우리 예산으로 살 수 있는 KV260 급은 Stratix 10 보다 훨씬 작다.
DSP 슬라이스 수로 어림하면 **한 자릿수 GFLOPS** 대다 [추정].

## 6. 그래서 설계했다 — 축소하되 진짜인 것

"4090을 만든다"는 기각이지만, **GPU 구조 자체를 만드는 것은 기각이 아니다.**
목표를 "성능"에서 **"구조 + 검증"** 으로 바꾸면 1인 + LLM 으로 도달 가능한 설계가 나온다.

### ORBIT-G — 결정론적 SIMT 컴퓨트 코어 (설계 초안)

**한 줄**: 그래픽 고정기능을 **버리고**, SIMT 컴퓨트 코어만 만들되,
**모든 연산 결과가 골든 모델과 비트 단위로 일치하는** GPGPU.

왜 이 각도인가: NVIDIA/AMD 는 IEEE 부동소수 + 비결정적 리덕션 순서라
**같은 커널을 두 번 돌려도 결과가 다를 수 있다.** 우리가 DR1 에서 이미 하고 있는
**결정론 + 비트 정확 검증**은 그들이 안 하는 축이고, 우리 자산이 그대로 이어진다.

#### 6.1 아키텍처

```
                    ┌──────────────── ORBIT-G Core ────────────────┐
  PCIe/AXI ──► 명령  │  Warp Scheduler (W개 워프, 라운드로빈)          │
  (reg_top 재사용)   │      ├─ Fetch/Decode (RV32IM + SIMT 확장)     │
                    │      ├─ Scoreboard (in-order, 스톨 기반)       │
                    │      ▼                                        │
                    │  Lane 0 .. Lane 31  (32-wide SIMT)            │
                    │      ├─ INT ALU                               │
                    │      ├─ Q1.15 / Q2.30 MAC  ◄── mac_pe 재사용   │
                    │      └─ (선택) FP32 FMA                        │
                    │  Register File: 32 lane × 32 reg × 32b (BRAM) │
                    │  Divergence Stack (IPDOM, 깊이 8)              │
                    └──────┬─────────────────┬──────────────────────┘
                           │                 │
                    Shared Scratchpad     L1 D$ (직접 매핑)
                    (뱅크 32개)            │
                                          ▼
                                    외부 메모리 (DDR/HBM)
```

**핵심 설계 결정 5개**

| # | 결정 | 이유 |
|---|---|---|
| D1 | ISA 는 **RV32IM + SIMT 확장** (`tmc`/`wspawn`/`split`/`join` 계열) | 컴파일러를 새로 안 만든다. LLVM RISC-V 백엔드에 얹는다. Vortex 가 증명한 경로 |
| D2 | 워프 폭 **32**, 워프 수 **4~8** | 32 는 BRAM 폭·마스크 레지스터와 잘 맞는다. 워프 수는 FPGA 용량으로 결정 |
| D3 | 발산 처리는 **IPDOM 스택** (하드웨어) | 소프트웨어 마스킹보다 컴파일러가 단순해진다 |
| D4 | **FP32 는 선택 사항, 기본은 고정소수** | 우리 검증 체계(비트 정확)가 고정소수에서 성립한다. FP 는 IEEE 반올림까지 맞춰야 해서 검증 비용이 폭증 |
| D5 | **그래픽 고정기능 없음** | 래스터·텍스처·ROP·RT 전부 범위 밖. 넣는 순간 적합성 절차(7축)가 따라온다 |

#### 6.2 소프트웨어 스택 (이게 하드웨어보다 크다)

```
  사용자 커널 (OpenCL C)
        ↓  Clang/LLVM  (RISC-V 백엔드 + SIMT 내장함수)
  ORBIT-G 바이너리
        ↓  POCL 런타임 (디바이스 백엔드 하나 구현)
  liborbitg.so  ── ioctl ──►  커널 드라이버 (char device, DMA, 인터럽트)
        ↓
  하드웨어
```

- **컴파일러**: LLVM 백엔드를 **새로 안 만든다.** RISC-V 백엔드 + 내장함수 + 커스텀 패스.
- **런타임**: POCL 의 디바이스 백엔드 1개. OpenCL API 전체를 구현하지 않는다.
- **커널 드라이버**: 이 레포에 **이미 `driver/` 와 `tools/orbit_device.py` HAL 이 있다.** 이어진다.
- **Vulkan/DirectX 없음.** 적합성 절차를 **의도적으로 건드리지 않는다** (3.2절).

#### 6.3 검증 계약 (DR1 방식 그대로 확장)

| 계층 | 골든 | 판정 |
|---|---|---|
| 명령 1개 | `sim/golden/isa.py` 의 동명 함수 | 비트 일치 |
| 워프 1개 | 골든 인터프리터 | 레지스터 파일 전체 비트 일치 |
| 커널 1개 | numpy 참조 | 출력 버퍼 비트 일치 |
| 발산 | 골든이 같은 IPDOM 스택을 흉내 | 실행 마스크 열 비교 |

**오류 주입 필수** — DR1 하네스처럼, 고의로 1비트 틀린 DUT 를 넣어
테스트가 살아 있는지 증명한다. 이게 없으면 "전부 통과"는 아무 의미가 없다.

#### 6.4 단계와 게이트 (제안 — 승인 대기)

| 단계 | 산출물 | 기간 [추정] | 게이트 |
|---|---|---|---|
| G-0 | 골든 ISA 인터프리터 (RTL 0줄) | 2주 | 명령 전부 골든 통과 |
| G-1 | 1레인 스칼라 코어 + 골든 비트 일치 | 3주 | `synth_gate` EXIT=0 |
| G-2 | 32레인 SIMT + 발산 스택 | 4주 | 발산 커널이 골든과 일치 |
| G-3 | 스크래치패드 + L1 + DMA | 3주 | 행렬곱 커널 실행 |
| G-4 | LLVM/POCL 연결, `saxpy` 실행 | 4주 | 호스트에서 OpenCL 커널 실행 |
| G-5 | KV260 보드 실동작 | 2주 | 보드에서 커널 1개 결과 일치 |

**합계 약 18주.** 이건 `docs/PLAN.md` 12주 계획이 끝난 **뒤에** 시작하는 것이다.
**성능 목표를 숫자로 걸지 않는다** — 5절대로 FPGA 에서는 한 자릿수 GFLOPS 이고,
그걸 "GPU 를 만들었다"로 포장하면 `CLAUDE.md` 0절 위반이다.

## 7. DR1 과 ORBIT-G 비교

| | **ORBIT-DR1** (현재) | **ORBIT-G** (설계안) | RTX 4090 |
|---|---|---|---|
| 무엇 | 델타룰 헤드 **연산기 1개** | **범용 SIMT 코어** | 범용 GPU + 그래픽 |
| 현재 상태 | `INIT`/`DUMP` 동작, `STEP` W7 | **문서만** | 상용 제품 |
| RTL 규모 | 6개 모듈, `dr1_top` 8,808셀 | [추정] 20~40개 모듈 | 763억 트랜지스터 |
| 소프트웨어 | HAL + 디스크립터 (있음) | **LLVM + POCL + 드라이버 (큰 일)** | 드라이버 수천만 줄 [추정] |
| 프로그래밍 | 디스크립터 3개 | **OpenCL C** | CUDA/Vulkan/DX |
| 검증 | 골든 비트 일치 (동작 중) | 같은 방식 확장 | 회사 내부 |
| 남은 기간 | **6주** | +18주 | — |
| 위험 | 사이클 예산 104 vs 64 | 소프트웨어 스택 전체 | — |

**가장 큰 차이**: DR1 은 **6주 뒤 끝난다.** ORBIT-G 는 거기서 **다시 18주**다.
그리고 ORBIT-G 의 절반 이상은 하드웨어가 아니라 **컴파일러·런타임·드라이버**다.

## 8. 결론

1. **"RTX 4090급 그래픽카드"는 기각한다.** LLM 이 바꾸는 축(RTL 작성, 드라이버 코드,
   검증)은 전체의 절반이 안 되고, 못 바꾸는 축이 **전부 치명적**이다:
   테이프아웃 $40~50M, GDDR6X 조달 불가, EDA·PDK 계약, 적합성 절차, 게임 실측.
   특히 **메모리는 돈이 있어도 규격을 못 산다** (4절).
2. **FPGA 로도 4090급은 불가능하다.** 이 분야 최고 오픈소스인 Vortex 가
   25.6 GFLOPS 다 — **3,200배** 차이 (5절).
3. **그러나 "GPU 구조를 만든다"는 가능하다.** 성능이 아니라 **구조와 검증**을 목표로
   하면 6절의 ORBIT-G 가 나온다. 이건 진짜로 만들 수 있고, DR1 의 골든 검증 체계와
   `driver/`·`reg_top` 자산이 그대로 이어진다.
4. **다만 지금 방향을 틀지 않는다.** DR1 은 6주 남았고, 그게 유일하게
   "외부에 보여줄 완성물"을 만든다. 미완성 두 개보다 완성 하나가 낫다.
   ORBIT-G 는 W12 이후 후보로 이 문서에 세워 둔다.
