# DESIGN.md — ORBIT-DR1: 상태 고정 델타룰 헤드

버전 0.1 (2026-09). 이 문서는 SSOT다. RTL·골든 모델·테스트가 이 문서와 다르면 문서를 먼저 고친다.

## 1. 한 문단 요약

ORBIT-DR1은 **델타룰 계열(Gated DeltaNet / Kimi Delta Attention / RWKV-7 형태) 순환 층의 헤드 하나**를 하드웨어로 구현한다.
d×d 상태 행렬 S를 온칩 SRAM에 상주시키고, 토큰마다 (1) 감쇠, (2) 랭크-1 외적 갱신, (3) 상태-벡터 곱 읽기를 수행한다.
기존 `mac_array`(출력 고정 외적 누산)가 (2)의 핵심이며, 기존 제어 평면(디스크립터 큐, IRQ, 트레이스)이 호스트 인터페이스다.
GEMM 가속기는 세상에 넘치지만, **상태를 HBM에 왕복시키지 않는 갱신 유닛**은 2026년 현재 공개된 것이 없다. 그것이 이 설계의 존재 이유다.

## 2. 수학 (골든 모델의 정의)

토큰 t마다 입력 q_t, k_t, v_t ∈ R^d, 게이트 α_t ∈ (0,1], 학습률 β_t ∈ (0,1].

```
S_t = α_t · S_{t-1} · (I − β_t · k_t · k_tᵀ) + β_t · v_t · k_tᵀ      # 상태 갱신
o_t = S_t · q_t                                                    # 출력
```

하드웨어 친화형 전개 (같은 결과, 연산 순서만 고정):

```
p     = S_{t-1} · k_t                 # d×d · d  → d      (상태 읽기 1회)
err   = v_t − p                       # d
S_t   = α_t · S_{t-1} + β_t · err · k_tᵀ   # 스케일 + 외적 누산 (mac_array)
o_t   = S_t · q_t                     # 상태 읽기 1회
```

**주의**: α_t·S_{t-1}·(I−βkkᵀ) 를 그대로 전개하면 α·S − αβ·(S·k)·kᵀ 이므로, 위 전개에서 err = v − p 를 쓸 때 정확히는 `S_t = α·S − α·β·p·kᵀ + β·v·kᵀ`. 골든 모델은 이 정확한 식을 쓰고, RTL은 이것과 비트 단위로 일치해야 한다. (v − p로 단순화하는 것은 α=1일 때만 동일. 문서 v0.1에서 이 점을 명시함.)

## 3. 숫자 형식 (v1은 고정소수점, 결정적)

- v1: **Q1.15 고정소수점** (16비트, 부호 1 + 소수 15). 곱은 32비트, 누산은 40비트, 상태 저장은 Q1.15로 재양자화(반올림 방식: round-half-to-even 고정).
- 이유: 합성 가능, 결정적, 골든 모델과 비트 일치 검증이 쉬움. BF16은 v2.
- 골든 모델(`sim/golden/deltarule.py`)은 numpy int 연산으로 같은 반올림을 구현한다. float로 만든 뒤 변환하지 않는다.
- 오버플로 정책: 포화(saturate). 트레이스 링에 `SAT_EVENT` 기록.

## 4. 크기

| 파라미터 | v1 (시뮬/KV260) | v2 (Alveo) |
|---|---|---|
| d (헤드 차원) | 16 → 64 | 128 |
| 상태 S | 16×16 → 64×64 Q1.15 (8KB) | 128×128 Q1.15 또는 BF16 (32~64KB) |
| 동시 세션 수 | 1 | 4~16 (세션 = 상태 슬롯) |
| 토큰당 목표 사이클 | ≤ 4·d (64: ≤256) | ≤ 2·d |

v1은 **d=16으로 먼저 끝낸다** (기존 mac_array 그대로). 16에서 골든 일치 → 64로 확장. 64가 안 되면 16으로 끝낸 것을 성과로 보고한다.

## 5. 블록 구조

```
host (tools/ Python HAL, driver/)
  │  MMIO + descriptor (기존 reg_top / desc_queue / desc_fsm_v2)
  ▼
dr1_top  ── opcode DELTA_STEP / DELTA_INIT / DELTA_DUMP
  ├── state_sram      d×d Q1.15, 2R1W 또는 뱅크 분할 (v1: 단순 1R1W + 직렬)
  ├── matvec_unit     p = S·k, o = S·q      (행 단위 순회, d 사이클)
  ├── mac_array       S += β·err·kᵀ 외적 누산 (기존 모듈, acc를 상태와 결합)
  ├── scale_unit      S ← α·S  (행 단위 곱, matvec와 파이프라인 공유 가능)
  ├── vec_regs        q, k, v, err (각 d×16bit)
  └── perf/trace      토큰당 사이클, 포화 이벤트 → 기존 trace_ring
```

디스크립터(64B, 기존 `spec/descriptor.md` 확장):
- `DELTA_INIT {slot}` : 상태 슬롯을 0으로.
- `DELTA_STEP {slot, q_addr, k_addr, v_addr, o_addr, alpha_q15, beta_q15}` : 한 토큰 처리. 완료 시 IRQ.
- `DELTA_DUMP {slot, dst_addr}` : 상태 전체를 메모리로 (검증용).

v1의 데이터 경로는 기존 `act_sram`/`wgt_sram`처럼 **온칩 SRAM 스크래치**에서 q/k/v를 읽는다. DDR/PCIe는 v1 범위 밖이다. 호스트는 MMIO로 스크래치를 채운다(느려도 됨).

## 6. 사이클 예산 (d=64, v1 목표)

| 단계 | 사이클 | 비고 |
|---|---|---|
| p = S·k | 64 | 행마다 64-MAC 내적 1개/사이클 |
| err, β·err | 2 | 벡터 연산 |
| S ← α·S + β·err·kᵀ | 64 | 행 단위: 읽기-스케일-외적-쓰기 |
| o = S·q | 64 | |
| 오버헤드 | ~16 | 디스크립터, IRQ |
| **합계** | **~210** | 목표 ≤ 256 ✔ |

100MHz FPGA에서 토큰당 ≈ 2.1µs/헤드. 느리다. **v1의 목적은 속도가 아니라 "상태가 칩을 떠나지 않는 정확한 갱신"의 증명**이다.

## 7. 검증 계약

모든 테스트는 다음 순서를 따른다:
1. `sim/golden/deltarule.py`로 무작위 시드 N 토큰 시퀀스의 S_t, o_t 생성 (Q1.15 정수 연산).
2. cocotb가 같은 입력을 RTL에 넣고 `DELTA_DUMP`로 상태를 꺼내 **비트 단위 비교**.
3. 불일치 시 첫 불일치 토큰 인덱스, 행, 열, 기대/실제 값을 출력.

불변조건 (매 테스트 마지막에 검사):
- I1. `DELTA_INIT` 후 상태는 전부 0.
- I2. α=1, β=0이면 상태는 변하지 않는다.
- I3. β=0이면 o_t = S_{t-1}·q_t 와 일치.
- I4. 포화가 일어난 토큰 수 == 트레이스 링의 `SAT_EVENT` 수.
- I5. 같은 입력·같은 시드 → 두 번 실행 결과 동일 (결정성).

합성 게이트: `yosys synth -top dr1_top` 통과, `verilator --lint-only -Wall` 경고 0 (의도된 UNUSED 제외).

## 8. 기존 코드 재사용 지도

| 기존 | 용도 | 변경 |
|---|---|---|
| `mac_array.sv`, `mac_pe.sv` | 외적 누산 | acc 초기값을 α·S 행으로 로드하는 경로 추가, 또는 별도 가산기로 S와 합산 |
| `act_sram.sv`, `wgt_sram.sv` | q/k/v 스크래치 | 그대로 |
| `reg_top`, `desc_queue`, `desc_fsm_v2`, `irq_ctrl`, `trace_ring`, `reset_seq` | 제어 평면 | opcode 3개 추가 |
| `gemm_top`, `ctrl_fsm` | 참고용 FSM 패턴 | `dr1_top` FSM의 본보기 |
| `kvc_core.sv` | v2에서 세션 슬롯 관리 참고 | v1 미사용 |
| `tools/orbit_desc.py`, `orbit_mmio_map.py` | 디스크립터 패킹, 레지스터맵 | 새 opcode·레지스터 추가 (SSOT 유지) |

사용 안 함 (격리): `rtl/behavioral/`로 이동하는 `real` 사용 7개 모듈, G3 학습 경로 전체, `mxu_bf16_128x128`.

## 9. 알려진 위험

- 64×64 상태를 1R1W SRAM으로 매 토큰 2회 읽기 + 1회 쓰기 → 뱅크 충돌. v1은 직렬로 피하고, v2에서 뱅크 분할.
- Q1.15 상태는 장시간 누적 시 정밀도 손실. 골든 모델로 1,000토큰까지 비트 일치를 확인하고, 그 이상은 v2(BF16) 과제로 넘긴다.
- 델타룰 변형이 논문마다 다르다(정규화, 게이트 위치). v1은 2절 식 하나로 고정하고 다른 변형은 골든 모델 옵션으로만 둔다.
- `done_pulse` 계열 버그가 dr1_top FSM에서 재발할 수 있다. 완료 신호는 "상태 쓰기 완료 후 1사이클"로 명시하고 파형(GTKWave)으로 확인한다.

## 10. 이 설계가 하지 않는 것

학습(역전파), 어텐션, 소프트맥스, 정규화, 활성함수, 다중 헤드 병렬, DDR/HBM, PCIe 실동작, BF16. 전부 v2 이후이거나 이 레포 범위 밖이다.
