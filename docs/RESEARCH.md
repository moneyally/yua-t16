# RESEARCH.md — 빈 질문 조사 (ORBIT-DR1)

버전 0.1 (2026-09-11). **계획 문서다. 실험은 아직 하나도 돌리지 않았다.**

## 0. 이 문서의 규칙 (어기면 문서를 되돌린다)

1. **발명 주장 금지.** "새롭다", "최초", "아무도 안 했다" 를 쓰지 않는다.
   여기 있는 것은 *검색해도 답을 못 찾은 질문* 이지, *답이 없는 질문* 이 아니다.
2. **어떤 아이디어도 검색 결과 없이 평가하지 않는다.** 각 질문마다 실제로 던진
   검색 질의문과 나온 논문을 적는다. 논문 **본문은 못 읽었다** (arxiv.org 가 이
   컨테이너에서 egress 프록시에 막힌다) — 전부 제목·초록 수준이다.
3. **RTL 금지.** 이 조사는 `sim/golden/` 만 건드린다.
4. **실험 실행은 승인 후.** 3절의 계획은 제안이다.
5. 출처 등급은 `docs/PRIOR_ART.md` 0절과 같다: **[검색]** / **[사용자]** / **[추정]**.

## 1. 처음 세운 질문 4개와, 검색 후의 결론

원래 질문(세션 10 지시): Q-A 고정소수 장기 오차 / Q-B 게으른 감쇠 /
Q-C 세션 상주 스케줄링 / Q-D 헤드 간 상태 공유·압축.

**검색 결과 4개 중 2개는 이미 답이 나와 있었고, 2개는 흡수·재정의됐다.**

| 질문 | 선행 연구가 이미 답했나 | 근거 |
|---|---|---|
| **Q-A** 고정소수 순환 상태의 장기 누적 오차, 오류 피드백·확률적 반올림·주기적 재정규화 | **부분** | 2절 A-표. → **Q-F 로 흡수** |
| **Q-B** 스칼라 c 로 감쇠를 미뤘다가 나중에 반영 | **예** | DeltaLog 2608.15533 이 더 일반적인 형태로 이미 함 → **Q-E 로 흡수** |
| **Q-C** 세션 상태 상주 스케줄링 | **예 (닫는다)** | 2절 C-표. 하드웨어 co-design 사례까지 있다 |
| **Q-D** 헤드 간 상태 공유·압축 | **예 (닫는다)** | 2절 D-표. 2026년에 여러 편 |

남은 것은 **Q-E**, **Q-F** 두 개다. 둘 다 "아니오" 가 아니라 **"부분"** 이다.

## 2. 질문별 선행 연구

### C. 세션 상주 스케줄링 — **닫는다**

검색 질의: `multi-session state residency scheduling on-chip memory LLM serving stateful sessions accelerator eviction policy` [검색]

| 논문 | 내용 | Q-C 와의 관계 |
|---|---|---|
| **UNISON**, arXiv 2609.09643 — *A Co-Designed Near-Memory Scheduler of Session KV Residency for LLM Agents* | 공유 KV 풀에서 **세션 단위 상주 순위**를 매기는 제어 평면 IP. 메모리 계층에 결선되어 **사이클 단위로 이벤트를 관찰**, 소프트웨어 개입 없음 | 내가 Q-C 로 적으려던 것과 **같은 문제, 같은 층위(하드웨어)** 다 |
| **TOPAS**, arXiv 2608.25523 | prefix 상주를 워크플로 수준 스케줄링 결정으로 명시적으로 다룸 | 상위 층 |
| **Talaria**, arXiv 2607.17181 | 세션 연속성을 배치·수용 결정으로 | 상위 층 |

→ **Q-C 는 연구 질문이 아니다.** DR1 이 다중 슬롯(v2)으로 갈 때 **읽을 문헌**이다.

### D. 헤드 간 상태 공유·압축 — **닫는다**

검색 질의: `sharing or compressing recurrent state across attention heads linear attention low-rank state compression 2026` [검색]

| 논문 | 내용 |
|---|---|
| arXiv **2602.04852** — *The Key to State Reduction in Linear Attention: A Rank-based Perspective* (OpenReview 공개) | 학습된 선형 어텐션의 연상 메모리가 **저랭크**다. 학습 후 상태를 크게 줄여도 성능 손실이 작다. key/query 채널 **50~75% 제거 가능** |
| arXiv **2602.02195** — *State Rank Dynamics in Linear Attention LLMs* | 헤드가 저랭크/고랭크로 **층화**되고, 그 성질이 사전학습 중 굳는다 |
| arXiv **2603.02188** — *Multi-Head Low-Rank Attention* (ICLR 2026) | 저랭크 제약 + 멀티헤드 |
| arXiv 2505.23666 — *LoLA: Low-Rank Linear Attention With Sparse Caching* | 저랭크 + 희소 캐시 |

→ **Q-D 도 연구 질문이 아니다.** "d×d 를 통째로 들고 있을 필요가 없다" 는 이미 답이 나왔다.
DR1 v2 의 상태 크기 결정에 **입력으로 쓸 결과**다.

### A/F. 고정소수 장기 안정성 — **부분**

검색 질의:
`fixed-point saturation versus soft clipping tanh recurrent state stability hardware accelerator quantized RNN long context`,
`saturation overflow counter feedback control hardware accelerator dynamic rescaling fixed-point neural network runtime` [검색]

| 논문 | 내용 | 겹치는 부분 / 안 겹치는 부분 |
|---|---|---|
| **SANE**, arXiv 2608.22354 [사용자] | RWKV-7 **1억 토큰**에서 국소 채널 노름 폭발. **청크 경계 tanh 적응 압축(3≤α≤5)**. α≥8 은 안정하지만 추론 상실 | 겹침: "장기 상태가 터진다, 청크 경계에서 누른다". 안 겹침: **부동소수 알고리즘** 이야기다. 고정소수 하드 클립은 다루지 않는다 |
| arXiv **2607.04531** — *Lyapunov-Guided Training for Hardware-Safe Neural Networks Under Fixed-Point Arithmetic* | 고정소수에서 **2의 보수 래핑**이 상태를 손상시킨다. 층별 은닉 상태 **에너지 상한**을 학습으로 강제 | 겹침: 고정소수 안정성. 안 겹침: **학습 시 제약**이지 추론 하드웨어 정책이 아니다. DR1 은 학습을 안 한다 |
| arXiv **2304.11790** — *Adaptive-saturated RNN* | 포화를 적응적으로 | 부동소수, 학습 |
| arXiv **1512.01322** — *Fixed-Point Performance Analysis of RNNs* | 고정소수 RNN 오차 분석의 고전 | 겹침 크다. **본문 확인 필요** |

**남는 틈 (가설, 주장 아님)**: 위 어느 것도 **"이미 세고 있는 포화 카운터(`SAT_EVENT`)를
제어 신호로 되먹이는 추론 하드웨어 정책"** 을 다루는 것으로 보이지 않는다.
다만 **본문을 안 읽었으므로 "없다" 고 쓰지 않는다.**

### B/E. 지연 병합을 온칩에 — **부분**

검색 질의: `FPGA accelerator deferred state update lazy decay linear attention hardware fixed-point recurrent state write elimination`,
`delta rule outer product update on-chip SRAM fixed point Q1.15 FPGA accelerator merge period error analysis` [검색]

| 논문 | 내용 | 관계 |
|---|---|---|
| **DeltaLog**, arXiv 2608.15533 [사용자] | dense base + 유계 로그, 주기 병합, 의미 불변. GDN/KDA/RWKV6. 커널 1.86×, 상태 쓰기 트래픽 7.83× | **같은 아이디어의 일반형.** 단 **cs.DC, GPU 서빙 스택 소프트웨어** |
| **2603.05931** [사용자] | 온칩 상주 FPGA, 토큰당 **읽기 1 + 쓰기 1** | 하드웨어지만 **지연 병합은 안 한다** (매 토큰 쓴다) |

두 검색 모두에서 **"온칩 고정소수에서 지연 병합"** 사례는 나오지 않았다.
두 번째 검색은 Q1.15·병합 주기·오차 분석에 대해 **아무것도 못 찾았다** (검색 엔진이
"해당 주제의 문서가 없다" 고 명시).

**남는 틈 (가설)**: 층위. GPU 는 쓰기 트래픽(대역폭)이 문제고, DR1 은 **SRAM 포트와
사이클 예산**이 문제다. 그리고 고정소수에서는 **병합을 미룰수록 로그 항의 재양자화가
달라진다** — 소프트웨어(FP)에서는 "의미 불변"이지만 **고정소수에서는 불변이 아닐 수 있다.**
이것이 실제로 그런지가 측정 가능한 질문이다.

## 3. 1주 안에 골든 모델로 할 수 있는 것 — **Q-F 를 제안한다 (승인 대기)**

### 왜 Q-F 인가 (Q-E 가 아니라)

| | Q-E (지연 병합) | **Q-F (클립 정책)** |
|---|---|---|
| 골든만으로 답이 나오나 | **아니오.** 이득이 사이클·SRAM 포트에 있어서 하드웨어 비용 모델이 필요하다 | **예.** 전부 수치 실험이다 |
| 1주 안에 되나 | 병합 로그 모델 + 비용 모델 = 2주 이상 | 골든에 클립 옵션 1개 추가 |
| DR1 에 이미 있는 것을 쓰나 | 없음 (새 구조) | **`SAT_EVENT` 카운터가 이미 있다** (`DR1_SAT_COUNT`) |
| 위험 | 고정소수 "의미 불변" 가정이 깨지면 골든 자체가 바뀐다 | 골든은 그대로 두고 **옵션**으로 추가 |

Q-E 는 **W8 이후**로 미룬다 (DESIGN 9절의 패스 융합 과제와 같은 자리다).

### Q-F 실험 계획 (승인 후 실행)

**질문**: Q1.15 **하드 클립**(현재 DR1)과 **tanh 소프트 클립**(SANE 계열)은
장기 구동에서 상태 오차·정보 보존이 어떻게 다른가. 그리고 **이미 세고 있는 포화
횟수를 압축 트리거로 쓰면** 둘 사이 어디에 앉는가.

**변경 대상**: `sim/golden/deltarule.py` **만**. RTL 0줄.
기존 `step()` 의 기본 동작은 **바뀌지 않는다** (옵션 인자 기본값 = 지금 동작).
`tests/test_golden_deltarule.py` 의 기존 21개 테스트가 전부 그대로 통과해야 한다 —
그것이 "골든을 안 망가뜨렸다" 는 증거다.

**추가할 정책** (`clip_policy=`):

| 값 | 동작 |
|---|---|
| `"hard"` (기본, 현재) | `requantize_q15` 의 포화 그대로 |
| `"tanh_chunk"` | C토큰마다 상태 행별로 tanh 적응 압축. 계수는 SANE 의 3~5 범위를 **고정소수로 옮겨서** 격자 탐색 |
| `"sat_triggered"` | 청크 안에서 포화가 T회 넘게 나면 그 청크 끝에만 압축 |

**측정** (전부 정수, float 참조와 비교):

1. **드리프트**: float64 참조 대비 S 의 최대 LSB 오차 — 토큰 100 / 1,000 / 10,000
   (현재 골든 자체 테스트가 100토큰에서 2.1 LSB 를 기록하고 있다. 그 연장선이다)
2. **포화 횟수**: `sat_count` 누적 (RTL `DR1_SAT_COUNT` 와 같은 정의)
3. **정보 보존 대리 지표**: `o = S·q` 의 코사인 유사도 (float 참조 대비).
   SANE 의 "α≥8 은 안정하지만 추론 상실" 에 대응하는 축이다 — **압축이 과하면
   안정성은 좋아지고 이 지표가 떨어질 것**이라는 예측을 검사한다
4. 조건: d=16, 64 × 시드 3개 × α∈{0.9, 0.99, 1.0} × β∈{0.1, 0.5}

**성공/실패 기준 (미리 적는다 — 나중에 고르지 않기 위해)**

- 하드 클립이 10,000토큰에서 **드리프트 폭주(>100 LSB)** 하지 않으면,
  **Q-F 는 DR1 v1 에 불필요하다** 는 결론이고 그대로 기록한다. 실패가 아니다.
- tanh 청크 압축이 드리프트를 **절반 이하**로 줄이면서 코사인 유사도를 **0.99 이상**
  유지하면 W8 이후 RTL 후보다.
- `sat_triggered` 가 항상 압축하는 것과 같은 결과면, **트리거가 의미 없다**는 뜻이다.

**산출물**: `docs/RESEARCH.md` 에 표 + `sim/golden/` 에 실험 스크립트 1개.
**논문 주장은 하지 않는다.** 숫자만 남긴다.

**예상 비용**: 골든 수정 반나절, 측정 실행 반나절 (10,000토큰 × 조건 36개는
파이썬 정수 연산이라 느리다 — 필요하면 d=64 를 1,000토큰으로 줄인다).

## 4. 승인이 필요한 것

1. **Q-F 를 1주 실험으로 진행할지.** (Q-E 는 W8 이후로 미루는 것에 동의하는지)
2. Q-C·Q-D 를 **닫는 것**에 동의하는지. 닫으면 DR1 v2 설계 때 "읽을 문헌" 으로만 남는다.
3. 논문 본문이 필요하면 **PDF 를 받아 붙여줘야 한다** — 이 컨테이너에서 arxiv.org 가
   막혀 있다. 특히 **1512.01322** 와 **2608.15533** 은 본문을 봐야 Q-E/Q-F 의
   "부분" 판정을 "예" 로 바꿀지 결정할 수 있다.
